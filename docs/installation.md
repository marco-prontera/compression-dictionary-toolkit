# Installation

Builds require Node.js 22.12 or newer, npm, Zstandard CLI 1.5.5 or newer, and Brotli CLI with `-D` / `--dictionary`. Development uses Node 24 and Brotli 1.2.0. Encoders are required for builds and decoder tests, not for serving prepared releases.

For repository development, use Node 24 (`nvm use`). The lint tooling requires Node 22.13+ on the 22.x line, or Node 24 and newer. The published package retains its Node 22.12 minimum.

## Install the toolkit

```sh
npm install compression-dictionary-toolkit
```

The same package exports the core, `/vite`, `/server`, and `/edge`. Install Vite separately when using the plugin. Before registry publication, install the tarball generated by `npm run pack:release` instead. The `shared-dict` CLI is included.

## Encoder package managers

```sh
# macOS
brew install zstd brotli

# Debian/Ubuntu
sudo apt-get install zstd brotli
```

Check the supplied Brotli version: 1.0.x lacks dictionary support. A binary on `PATH` alone is insufficient.

```sh
npm ci
npm run doctor
npm test
npm run check:types
```

`doctor` checks encoder availability and the Brotli dictionary option. Tests check actual compression and decompression. On Windows, WSL can use the Linux instructions; native Windows execution has not been verified. Custom executable paths can be provided through `ZSTD_BIN` and `BROTLI_BIN`.

## Build Brotli 1.2.0 locally

The following Linux procedure needs `curl`, `tar`, and a C compiler. It builds the official release without installing globally:

```sh
mkdir -p .tools/brotli-build
cd .tools/brotli-build
curl -fL https://github.com/google/brotli/archive/refs/tags/v1.2.0.tar.gz -o brotli-v1.2.0.tar.gz
tar -xzf brotli-v1.2.0.tar.gz
cc -O2 -DNDEBUG -DBROTLI_BUILD_PORTABLE -I brotli-1.2.0/c/include \
  brotli-1.2.0/c/common/*.c brotli-1.2.0/c/dec/*.c \
  brotli-1.2.0/c/enc/*.c brotli-1.2.0/c/tools/brotli.c \
  -lm -o brotli
export BROTLI_BIN="$PWD/brotli"
cd ../..
npm run doctor
npm test
```

Export `BROTLI_BIN` in every terminal that builds a release. The server does not need it. Upstream also documents a CMake build.

## Custom executable paths

```js
await prepareAsset({
    input: './dist/app.js',
    outDir: './dist',
    key: 'app',
    url: '/app.js',
    brotliBinary: '/path/to/brotli',
    zstdBinary: '/path/to/zstd',
});
```

Encoder failure aborts preparation without publishing a new manifest that claims missing representations. Preserve `.dictionary-store` when rebuilding.
